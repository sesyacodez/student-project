# Спринт: дочистка Фази 1 + старт Фази 2

**Мета спринту:** закрити прогалини Фази 1, які блокують REST і спеки, паралельно підняти **DRF + JWT**, маршрути **`/api/v1/`** і ключові ресурси за контрактом у [api-endpoints.md](./api-endpoints.md). Детальний поділ по фазах — у [rozpodil-roboty-komanda-fazy-1-3.md](./rozpodil-roboty-komanda-fazy-1-3.md).

**Час:** за домовленістю команди (наприклад 2–4 тижні); переглядати цей файл після кожної інтеграції.

---

| # | Хто | Що зробити |
|---|-----|-------------|
| 1 | Учасник 1 | User↔Branch, скелет DRF/JWT і `POST /auth/login/` (або еквівалент за документом) |

| 3 | Усі | Звірка URL і тіл запитів з [api-endpoints.md](./api-endpoints.md); увімкнути Swagger |

## Учасник 1 — ядро, доступ, JWT, філії, користувачі

### Фаза 1 (залишки)

- [ ] Модель **зв’язку користувач ↔ філія** (наприклад `UserBranch` / M2M `through`) + міграції — під вимоги спеки (лише свої філії) та поле `branches` у відповіді логіну в [api-endpoints.md](./api-endpoints.md).
- [ ] **Неактивний** користувач (`is_active=False`) **не** проходить логін.
- [ ] **Однакова** відповідь при невірному телефоні та невірному паролі (без підказки, п. 4.1 спеки).
- [ ] За потреби: узгоджені методи **archive/restore** для `Subject` у стилі `Branch` (якщо ще не зроблено).

### Фаза 2 (основна робота спринту)

- [ ] Залежності: **Django REST Framework**, **SimpleJWT** (+ blacklist для logout), **drf-spectacular** (або інший OpenAPI).
- [ ] `settings.py`: `REST_FRAMEWORK`, `SIMPLE_JWT`, підключення spectacular.
- [ ] `urls.py`: префікс **`/api/v1/`**, include роутера/модулів API.
- [ ] Реалізація ендпоінтів за документом: **секції 2 (auth)**, **3 (branches)**, **4 (users/staff + призначення на філії)**.
- [ ] **Permissions** і **фільтрація queryset** за філіями, доступними користувачу; TEACHER без адмінських списків.
- [ ] **Swagger/OpenAPI** відкривається і відображає схему безпеки (Bearer).

### Фронт (конкретні задачі — Учасник 1)

*Детальніший контекст: [frontend-fazy-ta-rozpodil-storinok.md](./frontend-fazy-ta-rozpodil-storinok.md). Базовий префікс API: **`/api/v1/`** — див. [api-endpoints.md](./api-endpoints.md).*

**Спільне для команди фронту (узгоджує Учасник 1):**

- [ ] Один файл стилів: наприклад `global.css` / `static/css/app.css` — створити, підключити в layout; інші лише дописують блоки в той файл.
- [ ] Один файл/модуль **HTTP-клієнта** (axios/fetch wrapper): заголовок `Authorization: Bearer <access>`, обробка **401** (спроба refresh або редірект на логін), парсинг тіла помилок **400** для показу в формах.

**Етап до появи API (можна паралельно з бекендом):**

- [ ] Скелет додатка (SPA або Django `base.html` + вкладені шаблони): **layout** з місцем під меню й контент.
- [ ] Роути (приклад для SPA — шляхи узгодити в команді): `/login`; після авторизації: `/`.

**Етап після готовності auth + branches/users API:**

- [ ] Сторінка **`/login`**: поля телефон + пароль → `POST /api/v1/auth/login/` → зберегти access (і refresh якщо є) → редірект на головну; при помилці показувати **узагальнене** повідомлення (без підказки «нема юзера»).
- [ ] **`GET /api/v1/auth/me/`** після входу: зберегти роль та список `branches` у стані/context для меню й фільтрів на інших екранах.
- [ ] **Захист маршрутів**: неавторизований користувач → тільки `/login`; **Вихід** → `POST /api/v1/auth/logout/` (якщо реалізовано) + очистити токени.
- [ ] **Меню:** ADMIN бачить посилання на всі екрани; TEACHER — тільки «Мій розклад», «Відвідуваність» (до своїх уроків — як домовиться з Учасником 3), без філій/студентів/тарифів.
- [ ] **`/branches`**: таблиця/список з `GET /branches/`; кнопка «Створити» → форма `POST /branches/`; рядок → перехід на **`/branches/:id`** з формою `PATCH`; кнопки «Архівувати» / «Відновити» → `POST …/archive/`, `POST …/restore/`.
- [ ] **`/users`** (лише сенс для ADMIN): список `GET /users/` з фільтрами з документа; створення/редагування staff; **призначення на філію** `POST /users/{id}/branches/` та зняття `DELETE /users/{id}/branches/{branch_id}/`.
- [ ] На всіх цих формах: відображення **структурованих помилок** з API (хоча б `message` + `details` як текст).

### Фронт (конкретні задачі — Учасник 2)

*Використовувати спільний HTTP-клієнт і `global.css` від Учасника 1. Для полів «філія» на формах — підставляти список філій з `auth/me` або окремий `GET /branches/` (узгодити).*

- [ ] **`/subjects`**: список `GET /subjects/?branch_id=…&status=…&search=…`; форма створення `POST /subjects/`; на рядку — редагування `PATCH`; кнопки архів/відновлення згідно [api-endpoints.md](./api-endpoints.md) §5.
- [ ] **`/students`**: список з фільтрами (`branch_id`, `status`, `group_id`, пошук); клік → **`/students/:id`** — картка студента + `GET/PATCH`; архів/відновлення.
- [ ] **`/groups`**: список; **`/groups/:id`** — деталі групи, список студентів `GET /groups/{id}/students/`; форма **додати** `POST /groups/{id}/students/` (student_id, join_date); кнопка **вилучити** `DELETE /groups/{id}/students/{student_id}/`.
- [ ] **`/subscription-plans`**: список з фільтрами; форма **створення плану** з полями branch, name, type, multiselect предметів, динамічні рядки **pricing tiers** → `POST /subscription-plans/` (тіло як у прикладі в документі API); редагування `PATCH`; призначення предметів `PUT …/subjects/` за потреби; керування рівнями цін через ендпоінти tiers з §8.
- [ ] **`/student-subscriptions`**: список з фільтрами; форма призначення `POST /student-subscriptions/` (student_id, plan_id, subject_id, start_date); перегляд/редагування одиниці `GET/PATCH`.

## Вихід спринту (definition of done)

1. Працює **JWT** (access + refresh за потреби rotation/blacklist — як у спеки та документі API).  
2. Ресурси з **секцій 2–12** api-endpoints реалізовані або явно відкладені з причиною в цьому файлі.  
3. Міграції застосовуються з нуля (`migrate`) без ручних костилів.  
4. Swagger показує основні теги та можливість викликати захищені ендпоінти з токеном.  
5. Тести: мінімум auth, конфлікти розкладу, один CRUD-ланцюжок по студенту/групі.  
6. Фронт: у кожного учасника закриті **всі** пункти в підрозділах «Фронт (конкретні задачі)» для своєї доріжки; спільний **global.css** і HTTP-клієнт у використанні; хоча б один повний сценарій демо з UI (не лише Swagger).
