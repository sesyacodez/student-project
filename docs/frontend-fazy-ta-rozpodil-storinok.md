# Фронтенд: фази, сторінки та розподіл між учасниками

Офіційний перелік екранів — у [student-project-spec.md](./student-project-spec.md), розділ **5. Frontend Requirements**. Нижче — **коли** це робити за фазами курсу і **хто** веде яку сторінку у моделі «кожен — свій блок + один глобальний CSS».

---

## Як фази курсу стосуються фронту (узагальнення зі спеки)

| Фаза курсу | Що очікується від фронту |
|------------|---------------------------|
| **Фаза 1** | Мінімальний UI: можна **Django Templates** або початок SPA — **достатньо показати** моделі + автентифікацію (наприклад форма логіну, 1–2 екрани-заглушки). Повний REST ще не обов’язковий. |
| **Фаза 2** | Головна робота: **усі дані лише через REST API**, підключити реальні запити до бекенду (п. 5–6 спеки). Функціонал важливіший за вигляд. |
| **Фаза 3** | **Допіл:** зрозуміліші помилки, стабільність, при потребі адаптив — «фінальна версія для демо» (п. 7 Phase 3). |

Практично: екран з **Фази 1** можете зробити статичним/формою на сесію; **з Фази 2** той же маршрут перепідключаєте на JWT + fetch/axios. **Фаза 3** — полірування без зміни власника сторінки.

---

## Один глобальний CSS (домовленість команди)

Щоб стилі не роз’їжджались між трьома учасниками:

1. **Один файл** для всіх базових стилів проєкту, наприклад:
   - Vanilla / SPA: `frontend/styles/global.css` — **одне** підключення в кожному HTML (`<link rel="stylesheet" href="styles/global.css">`) або в точці входу SPA.
   - Або Django Templates: `static/css/app.css` — **одне** підключення в базовому шаблоні `base.html`.

2. **Правило:** у компонентах/часткових шаблонах — тільки **класи** з узгодженого префікса (наприклад `.app-`) або просто семантика в `global.css`; **нові окремі `.css`-файли на сторінку не додаємо**, лише класи в тому самому глобальному файлі (можна блоками коментарями: `/* --- Учасник 2: студенти --- */`).

3. **Хто підтримує файл:** умовно **Учасник 1** (скелет додатка + layout); інші лише дописують свої блоки в **кінець** файлу або в окремі секції, без перейменування чужих класів без узгодження.

Стек фронту (React / Vue / Templates) ви обираєте самі — структура з одним `global.css` однаково застосовна.

## Хто яку сторінку робить (3 учасники)

Нижче — відповідність **спеки п. 5** вашому розподілу бекенду. Кожен веде **свої маршрути** й підключає їх до **своїх** API-префіксів з [api-endpoints.md](./api-endpoints.md).

### Учасник 1 — «оболонка», вхід, філії, персонал

| Екран (спека) | API (орієнтир) | Фаза мінімум |
|---------------|----------------|--------------|
| **Логін** (номер телефону) | auth: login / refresh / me | Фаза 1 — форма; Фаза 2 — JWT |
| **Навігація за роллю** (layout, меню ADMIN vs TEACHER) | me + role | Фаза 1 — статичне меню; Фаза 2 — умовний рендер |
| Список / створення / редагування **філій** | branches | Фаза 2 основне |
| **Користувачі** (ADMIN/TEACHER), призначення **на філії** | users, branches-assignment | Фаза 2 |

Цей учасник зазвичай створює **корінь SPA** або **`base.html`**, підключає **`global.css`**, роутинг і guarded routes за токеном.

### Учасник 2 — предмети, студенти, групи, тарифи

| Екран (спека) | API (орієнтир) | Фаза мінімум |
|---------------|----------------|--------------|
| **Предмети**: список, створення, архів | subjects | Фаза 2 |
| **Студенти**: список, пошук/фільтри, картка | students | Фаза 2 |
| **Групи**: список, додати/прибрати студента | groups | Фаза 2 |
| **Тарифи**: створення планів, решітка цін, **призначення студенту** | subscription-plans, student-subscriptions | Фаза 2 |

### Учасник 3 — розклад, шаблони, відвідуваність, звіти + екрани вчителя

| Екран (спека) | API (орієнтир) | Фаза мінімум |
|---------------|----------------|--------------|
| **Розклад уроків** (таблиця/календар), створення уроку | lessons | Фаза 2 |
| **Шаблони** занять: створити й переглянути | lesson-templates | Фаза 2 |
| **Відвідуваність**: перегляд і редагування (ADMIN) | lessons … /attendance | Фаза 2 |
| **Звіти**: розклад викладача, статистика відвідуваності, (за спекою) агрегати по філії | reports | Фаза 2 (частину можна догнати на старті Фази 3, якщо API пізніше) |
| **Вчитель:** лише свій розклад | lessons (filtered) | Фаза 2 |
| **Вчитель:** відмітити відвідуваність по уроку | attendance | Фаза 2 |
| **Вчитель:** інфо про студентів своїх уроків | groups/students у контексті lesson | Фаза 2 |

## Коротка таблиця «фаза курсу → що робимо на фронті»

| Фаза | Дії |
|------|-----|
| **1** | Репозиторій фронту (якщо SPA), **`global.css`**, layout + **сторінка логіну** (хоч би без токена), можливо один спрощений список філій або заглушка «під API». |
| **2** | Підключити **всі** екрани з таблиць вище до **`/api/v1/`**, обробляти **401/403/400**, показ тексту помилок з сервера (п. 5 спеки). |
| **3** | Причесати UX помилки, узгодженість класів із `global.css`, підготовка до демо. |
